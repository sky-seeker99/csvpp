# CSVPP Verilog RTL・テストベンチ・TOP統合 AI連携仕様書 Ver.2.0

**版数:** 2.0  
**作成日:** 2026-10-19  
**対象:** CSVPP / CSV-Verilog Maker II  
**状態:** 実例に基づくAI連携設計仕様（生成・シミュレーション完了を保証するものではない）  
**前版:** CSVPP Verilog RTL生成 AI連携仕様書 Ver.1.0

## 1. 目的
自然言語の回路要求から、既存のCSVPP Excelテンプレートに従ってRTL、検証用テストベンチ、クロック、TOP接続、カバレッジモニタを生成するためのAI入出力・編集・検証手順を定める。**AIはCSVPP/CSV-Verilog Maker IIの既存生成ロジックを置き換えず、テンプレートの設計シートを編集する。**

## 2. 参照ファイルと優先順位
| 種類 | 入力 | 生成結果 | 主な設計シート |
|---|---|---|---|
| RTL | `csvveri_rtl.xlsx` | `model(1).v`（module `model`） | `model` |
| テストベンチ | `csvveri_test.xlsx` | `test.v`（module `test`） | `test` |
| 検証TOP・クロック・カバレッジ | `csvveri_top.xlsx` | `top.v`, `clk(1).v`, `cover(1).v` | `top`, `clk`, `cover` |
| コマンド参照 | `CSVPP_Verilog_Generation.xlsx` | ― | マニュアルの該当項目 |
| 既存AI仕様 | `CSVPP_Verilog_RTL_AI連携仕様書_Ver1.0.md` | ― | RTLのAI編集原則 |

優先順位は、**マニュアルの正式なコマンド仕様 → 動作実績のあるExcel入力例 → 生成されたVerilog**とする。相違があれば推測で修正せず、差異を記録する。`model(1).v` と `test.v` は対応する一組の実例として扱う。

## 4. 編集権限と共通原則
- AIの通常編集対象は `model`、`test`、`top`、`clk`、`cover` シートの**既存記述規則に従う設計データ**に限定する。
- 各ブックの `cmd`、`csvveri_C` は原則保護する。既存のマクロ、クラス、実行コマンド、数式、参照、結合セル、書式を壊さない。
- 既存行を複製・追加するときは、コマンド列・引数列・ブロック境界・セル参照・順序を実例に照らして確認する。
- マニュアルに存在するコマンドとExcelに記入する `%` 系マクロは別レイヤーの可能性がある。**名称の類似だけで相互置換しない。**
- 保存後、シート一覧、保護対象差分、編集セル、生成ファイル一覧を記録する。削除や外部プログラム実行は利用者の実行環境を確認してから行う。

## 5. AI入力仕様
| 項目 | 必須条件 | 例・備考 |
|---|---|---|
| RTLモジュール | 必須 | `model` |
| ポート定義 | 必須 | 方向、信号名、ビット幅 |
| 機能・状態遷移 | 必須 | FSM、演算、ハンドシェイク、優先順位 |
| クロック | 順序回路で必須 | `clk`、エッジ、時間単位 |
| リセット | 使用時必須 | `reset_n`、極性、同期/非同期、解除タイミング |
| 刺激条件 | 検証で必須 | 初期化、入力変化、タイミング、境界値 |
| 期待値 | 自動判定で必須 | 出力ごとの期待値と許容条件 |
| カバレッジ目標 | 推奨 | 観測対象の条件、計測区間、合格基準 |
| 外部ファイル | 使用時必須 | ROM/HEXファイル、パス、形式、行数 |
| 実行環境 | 実行時必須 | シミュレータ、時間精度、ファイル配置 |

不明な信号方向、幅、期待値、時間単位、リセット極性はAIが黙って補完しない。仮定が必要なら明記して承認を求める。

## 6. RTL生成仕様：`csvveri_rtl.xlsx`
- `model` シートでモジュール、ポート、レジスタ、wire、assign、状態遷移、同期処理を記述する。
- 既存例では `model` の `B2=#module`、`C2=model`、`B5=%port`、`C5=clk`、`D5=input`、`E5=1` などの配置が確認されている（Ver.1.0参照）。
- 生成例 `model(1).v` の主なポート：入力 `clk`, `reset_n`, `cs`, `ad[31:0]`, `ack_i`、出力 `ack`, `cs_o`, `add[31:0]`, `data[31:0]`。
- 内部状態の例：`sample_acc`, `sample_idle`, `sample_wait`, `sample_wait2`。生成結果の `_CELL:[B35]` 等のコメントは原因追跡に利用する。
- 生成物は合成対象のRTLとみなし、テスト専用の時間遅延やファイルI/Oを安易に混入させない。

## 7. テストベンチ生成仕様：`csvveri_test.xlsx`
- `test` シートを使い、`test.v` の刺激・初期化・タスク・シーケンスを生成する。
- 実例の `test` は `clk`, `clko` を入力とし、`ack`, `cs_o`, `add[31:0]`, `data[31:0]` などRTL出力を観測し、`reset_n`, `cs`, `ad[31:0]`, `ack_i` などRTL入力を駆動する。
- 実例には `a_parm_fifo_rd`、`a_parm_fifo_wr`、`a_parm_ring_get` 等のタスクがある。FIFO/リング処理の内部意味やパラメータは該当マニュアル項目とExcel行を照合して確定する。
- AIはテストケースごとに**入力、開始条件、観測時刻、期待出力、終了条件**を明示する。
- `test.v` が刺激を生成できることと、期待値を自動判定できることは別。期待値比較・エラー数集計・終了コードの実装有無は個別に確認する。

## 8. TOP接続生成仕様：`csvveri_top.xlsx` / `top.v`
- `top` シートの接続表を編集し、`#con_head`、`#con_mod`、`#con` 等の正式な列・引数規則はマニュアルと元シートを参照する。
- 生成例 `top.v` は `module top;` を持ち、`clk i_clk`、`cover i_cover`、`model i_model`、`test i_test` をインスタンス化する。
- 主な結線：`clk` は `i_clk` から `i_model`、`i_test`、`i_cover` へ、`clko` は `i_clk` から `i_test` へ、`reset_n` は `i_test` から `i_model` へ接続する。
- `cs`、`ad`、`ack_i` はテスト側からRTL側へ、`ack`、`cs_o`、`add`、`data` はRTL側からテスト側へ流れる。
- TOPのワイヤ宣言・接続表に対し、ポートの存在、方向、ビット幅、単一ドライバ、未接続、名前の衝突を静的検査する。
- 実例の `test.v` は `rr_enable` 等も宣言するため、TOPにないテスト用ポートについては、意図的未接続か生成表の欠落かを区別してレビューする。

## 9. クロック生成仕様：`clk` シート / `clk(1).v`
- 実例は `clk` と `clko` の2出力を持つ。
- 生成コード上の `_clk` は `#500` で反転、さらに `#1500` で反転、残り `#(3000 - 500 - 1500)` 待機する。`_clko` は `#550`、`#1500`、残り `#(3000 - 550 - 1500)`。
- これらは**周期相当3000シミュレーション時間単位**の例であり、nsなどの物理単位は `timescale` / シミュレータ設定を確認するまで断定しない。
- `clk` と `clko` のエッジ差を利用する場合、リセット解除・入力更新・サンプリングの競合がないか確認する。
- 遅延パラメータは非負、周期内の遅延合計は周期以下であることをチェックする。

## 10. カバレッジ生成仕様：`cover` シート / `cover(1).v`
- 実例は `coverage_enable` を初期化し、`posedge clk` で階層信号を観測し、成立した項目の `cover_0` ～ `cover_5` を保持する。
- 監視例：`top.i_model.sample0_fp`、`sample1_fp`、`sample_acc`、`sample_idle`、`sample_wait`、`sample_wait2`。
- `coverage_start` と `coverage_result(3)` を呼び出す例がある。計測区間と結果表示の意味は生成コードのタスク定義で検証する。
- 監視先は `top.i_model` の階層に依存する。TOP名・インスタンス名・RTL内部信号名を変更した場合は連動更新する。
- この仕組みは**指定条件の到達確認**であり、網羅的な機能検証や出力期待値の正当性を単独では保証しない。

## 11. 共通信号台帳（AI内部の中間表現）
Excelを直接個別に作り始めず、まず次の表を確定する。

| 信号 | 幅 | ドライバ | 受信側 | 備考 |
|---|---:|---|---|---|
| `clk` | 1 | `i_clk` | `i_model`, `i_test`, `i_cover` | 主クロック |
| `clko` | 1 | `i_clk` | `i_test` | テスト用クロック |
| `reset_n` | 1 | `i_test` | `i_model` | アクティブLow |
| `cs` | 1 | `i_test` | `i_model` | 要求制御 |
| `ad` | 32 | `i_test` | `i_model` | アドレス等（機能は要照合） |
| `ack_i` | 1 | `i_test` | `i_model` | 応答入力 |
| `ack` | 1 | `i_model` | `i_test` | 応答出力 |
| `cs_o` | 1 | `i_model` | `i_test` | 制御出力 |
| `add` | 32 | `i_model` | `i_test` | 出力バス |
| `data` | 32 | `i_model` | `i_test` | 出力バス |

この表は提示された生成コードの**主要な信号に限定**したもの。`ss` / `rr` / `s_dt*` 等のテスト内補助接続は、別途全ポート抽出して追加する。

## 12. AI生成の手順
1. 要求を解析し、RTL機能、テストケース、期待値、カバレッジ条件を整理する。
2. モジュール・ポート・クロック・リセット・階層信号の共通台帳を確定する。
3. 元のExcel 3冊をバックアップし、保護対象シートを固定する。
4. `model` シートにRTL設計データを反映し、CSVPPでRTLを生成する。
5. RTLポート表を基に `test` シートへ刺激・観測・期待値条件を反映し、TBを生成する。
6. RTL/TBのポート表から `top` の接続表を作り、`clk` の周期・位相と `cover` の監視条件を設定する。
7. CSVPPでTOP・CLK・COVERを生成する。
8. 全生成物を静的照合し、未解決のポート、幅、階層、ファイル参照を報告する。
9. 対応シミュレータでコンパイル・実行し、期待値比較とカバレッジ結果を収集する。
10. 不具合を `_CELL:[...]` とExcel行へ戻し、修正→再生成→再検証する。

## 13. 実例で確認された注意点（要検証）
**以下は生成コード上の事実と、それに基づく確認事項であり、CSVPPの不具合と断定するものではない。**

1. `top.v` には `$readmemh("aaa.hex", FILE_ROM_00000)`、`$readmemh("bbb.hex", FILE_ROM_00000)`、`$readmemh("ccc.hex", FILE_ROM_00000)` が並ぶ。一方、`FILE_ROM_00001` と `FILE_ROM_00002` も宣言されている。意図したROMへのロード先か要確認。
2. `top.v` の `$dumpfile("c:\csv\aaa.dump")` はVerilog文字列中のバックスラッシュ解釈・シミュレータ依存性を確認する。保存先ディレクトリの有無も確認する。
3. `test.v` のポートには `rr_enable`、`rr2_enable` などがあるが、提示された `top.v` の `i_test` 接続には見当たらない。意図的な開放か接続漏れか要確認。
4. `cover(1).v` は `top.i_model` を参照するため、別名のTOPやインスタンスではそのまま利用できない。
5. `clk(1).v` の遅延値は生成例で確認できるが、時間単位の指定とシミュレータ対応は未確認。
6. 現段階ではコンパイル・実シミュレーションを実施した結果を含めない。**生成ファイルが存在することは、検証成功を意味しない。**

## 14. 自動検査と受入条件
| 段階 | 判定内容 | 合格基準 |
|---|---|---|
| Excel構造 | 必要シート・マクロ・参照の保持 | 保護対象の予期せぬ差分なし |
| 生成 | 5モジュールが生成される | `model`, `test`, `top`, `clk`, `cover` を確認 |
| 構文 | Verilog構文・モジュール解決 | コンパイルエラー0 |
| 接続 | ポート、幅、ドライバ、階層 | 未説明の不整合0 |
| 刺激 | クロック、リセット、テスト入力 | 予定したタイミングで発生 |
| 機能 | 期待値との照合 | 定義したテストケースの失敗0 |
| カバレッジ | 指定監視条件の到達 | 合意した目標値を満たす |
| 再現性 | 同一入力からの再生成 | 意図しない差分なし |

期待値比較が未実装の場合、機能合格とはせず「波形・到達確認のみ」と記録する。

## 15. AIへの標準指示テンプレート
```text
CSVPP / CSV-Verilog Maker IIを使ってVerilog RTLと検証環境を生成してください。
入力: RTL機能仕様、ポート表、クロック・リセット仕様、テストケース、期待値、カバレッジ目標。
参照: CSVPP_Verilog_Generation.xlsx、csvveri_rtl.xlsx、csvveri_test.xlsx、csvveri_top.xlsx。
編集: model / test / top / clk / cover シートの設計データのみ。
保護: cmd / csvveri_C、既存のマクロ・数式・書式・参照。
成果物: 編集済みExcel 3冊、生成Verilog 5モジュール、信号台帳、接続チェック、
         テストケース表、未確認事項、検証結果。
禁止: 未確認のコマンド構文の創作、勝手なマクロ改変、未実施の検証を成功と報告すること。
```

## 16. Ver.2.0の対象外と次版への課題
- AIからのCSVPP実行自動化、シミュレータ選定・導入、CI連携は環境確定後に設計する。
- `test` シートの全行・全コマンドについて、列位置・引数型・許容値・生成コード対応を抽出した**セルレベル記述規則表**を作成する。
- `top`、`clk`、`cover` の各コマンドについて、実例のセルアドレスと生成行を一対一で整理する。
- 期待値比較・テスト結果の機械判定・カバレッジ合格閾値の統一形式を定義する。
- 未接続ポートとROMロード先などの要検証事項を実機で確認し、回帰テストに組み込む。
