# CSVPP Verilog RTL生成 AI連携仕様書 Ver.1.0

**版数:** 1.0  
**作成日:** 2026-10-18  
**対象:** CSVPP / CSV-Verilog Maker II による Verilog RTL生成  
**位置づけ:** AI入力・Excel編集・コード生成・検証のための初版設計仕様

## 1. 目的
自然言語の回路仕様をAIが解析し、既存の `csvveri_rtl.xlsx` の書式に従って設計シートを作成・更新する。既存のCSVPPおよびCSV-Verilog Maker IIでVerilog HDLを生成し、生成結果を検証する。**AIは生成器の内部規則を推測して変更せず、提供されたテンプレートとマニュアルを正とする。**

## 2. 参照資料と優先順位
1. `CSVPP_Verilog_Generation.xlsx`：CSV-Verilog Maker II のコマンド仕様（25の説明・索引等シートと `work` シートを含む計26シート）。
2. `csvveri_rtl.xlsx`：動作実績のあるExcelテンプレート（`cmd`、`model`、`csvveri_C`）。
3. `model(1).v`：上記テンプレートから生成されたVerilogの実例。

仕様が曖昧な場合、マニュアルの記述、動作実績のあるテンプレート、生成結果の順に照合し、確定できない内容は「要検証」とする。

## 3. 対象範囲
### 3.1 Ver.1.0で扱う範囲
- RTLモジュール、ポート、信号、レジスタ、継続的代入の定義
- クロック・リセットと状態遷移の記述
- Excel設計データの作成、既存テンプレートへの反映
- 生成Verilogの構文・基本動作・設計仕様との照合
- セル位置コメントによる問題箇所の追跡

### 3.2 拡張候補（初版の自動生成対象外）
構造記述、モジュール間接続、task/function、メモリ、パイプライン、テストベンチ、FIFO、カバレッジなど。マニュアルに記述はあるが、各機能のAI生成規則は実例を用いて順次検証する。

## 4. システム構成
```text
自然言語によるRTL要求
       ↓
AI：仕様の構造化・矛盾検出
       ↓
AI：既存Excelテンプレートの設計行を編集
       ↓
csvveri_rtl.xlsx（cmd / model / csvveri_C）
       ↓
CSVPP（Excel→CSV、マクロ・クラス処理）
       ↓
CSV-Verilog Maker II（csvveri.exe）
       ↓
model.v
       ↓
構文チェック → シミュレーション → 仕様照合
```
CSVPPから生成器への受け渡し方法・実行パスは既存の `cmd` シートに従う。AIが生成器そのものを置き換える設計ではない。

## 5. 入力仕様（AIが受け取る情報）
| 項目 | 必須 | 内容 |
|---|---|---|
| モジュール名 | 必須 | Verilog識別子 |
| 入出力ポート | 必須 | 名前、方向、ビット幅 |
| クロック | 順序回路時 | 信号名、使用エッジ |
| リセット | 順序回路時 | 信号名、同期/非同期、極性、初期値 |
| 内部信号 | 必要時 | 名前、ビット幅、wire/reg相当の用途 |
| 状態遷移 | FSM時 | 状態、遷移条件、初期状態、優先順位 |
| 出力動作 | 必須 | 各出力の駆動条件と値 |
| 制約 | 推奨 | 使用禁止構文、クロックドメイン、タイミング条件 |

曖昧な仕様（未定義の信号幅、リセット値、競合する遷移条件等）は、Excelへの確定反映前に質問または未確定事項として提示する。

## 6. Excelテンプレート仕様
### 6.1 `cmd` シート
提供された実例では、B列に `%include`、`%classcall`、`%exec`、`%shell` 等が記載される。`%shell` 行では `csvveri.exe` の呼び出しと入力・出力ファイルの指定が行われている。**AIは原則このシートを変更しない。**

実例には `c:\csv\` への出力・削除指示があるため、実行環境の存在確認と、削除対象の事前確認を必須とする。既存データの削除コマンドをAIが無断で実行しない。

### 6.2 `model` シート
提供例の実際の先頭部分は次の通り。

| セル | 値 | 意味 |
|---|---|---|
| B2 | `#module` | モジュール定義の開始 |
| C2 | `model` | モジュール名 |
| B3 | `%header` | ヘッダ出力に関するテンプレート記述 |
| C3:F3 | `sample model`, `model`, `1.00`, `S.Kasuya` | ヘッダ情報 |
| B5 | `%port` | ポート定義 |
| C5 | `clk` | ポート名 |
| D5 | `input` | 入出力方向 |
| E5 | `1` | ビット幅 |
| B6 | `%port` | ポート定義 |
| C6:E6 | `reset_n`, `input`, `1` | リセット入力 |

**重要:** `model` シートにある `%port` 等は、マニュアルの `#port` 系記述と機械的に置換しない。テンプレートにはCSVPP側のマクロ・クラス処理が介在するため、同じ目的でもコマンド層が異なる可能性がある。AIが書き込む列・値は、同種の既存行をコピーしながら確認する。

### 6.3 `csvveri_C` シート
B2=`%class`、C2=`csvveri_C` というクラス定義があり、`%st` や `%alias` 等のマクロ定義を含む。**Ver.1.0では保護領域とし、AIによる自動変更は禁止する。**新しいコマンドが必要な場合は別途変更案を提出する。

### 6.4 編集上の制約
- シート名、既存の制御行、参照先、マクロ定義を保持する。
- データ行の挿入・複製は、前後のコマンド群・参照関係を確認して行う。
- セルの数式、書式、結合状態、名前付き範囲等を可能な限り維持する。
- 保存後に再読込し、変更対象以外の差分がないことを確認する。
- ファイル名・パス・文字コードは実行環境に合わせて検証する。

## 7. マニュアルにある主要コマンド群
以下はマニュアルの見出し・例で存在を確認できたもの。**ここに挙げた名前だけで引数形式が確定するわけではない。**

| 区分 | コマンド例 | 用途 |
|---|---|---|
| 基本定義 | `#header`, `#module` | ヘッダ、モジュール |
| 信号・RTL | `#wire`, `#reg`, `#assign`, `#reg_body`, `#wire_reg` | 信号、レジスタ、代入、追加動作 |
| 構造 | `#gate`, `#con_head`, `#con_mod`, `#con` | 部品・接続 |
| 関数等 | `#sub`, `#sparm`, `#slocal`, `#cmd` | task/function |
| 直書き | `#wr` | Verilogコードの直接出力 |
| テストベンチ | `#clk`, `#status`, `#chg`, `#patern` | クロック、状態、スケジューリング、パターン |
| 応用検証 | `#task`, `#taskn`, `#taskx`, `#coverage` | 周期タスク、カバレッジ |
| ファイル入力 | `#readmemh`, `#readvar` | テストデータの読み込み |

`#reg` のメモリ形式、レジスタAND-OR化、パイプラインなどは、各該当シートの書式・制限に従う。

## 8. AIの変換手順
1. **仕様解析**：ポート一覧、クロック、リセット、レジスタ、遷移、出力式を構造化する。
2. **静的整合性検査**：名前の重複、未宣言信号、幅の不一致、複数ドライバ、初期値・優先順位の不足を検出する。
3. **テンプレート照合**：`model` シートの類似記述行と、マニュアルの該当例を特定する。
4. **Excel作成**：`cmd` と `csvveri_C` を保持し、必要な `model` 行のみ更新する。
5. **差分確認**：変更したシート・行・セルを一覧化する。
6. **コード生成**：ユーザー環境のCSVPPとCSV-Verilog Maker IIで実行する。
7. **結果検証**：Verilog構文、信号宣言、クロック・リセット、状態遷移、出力条件を確認する。
8. **問題修正**：生成コードを直接恒久修正せず、原則Excelの設計行に戻って修正・再生成する。

## 9. 生成Verilogとの対応（実例）
`model(1).v` の実例では、次を確認できる。

- `module model` と、`clk`, `reset_n`, `cs`, `ad`, `ack_i`, `ack`, `cs_o`, `add`, `data` のポート。
- `sample_acc`, `sample_idle`, `sample_wait`, `sample_wait2` 等のレジスタ。
- `sample0_p` ～ `sample3_p` のwireと `assign` 文。
- `always @(posedge clk or negedge reset_n)` による非同期アクティブLowリセットのレジスタ制御。
- `// _CELL:[B35]` など、Excelのセル位置を示すコメント。

セル参照コメントは、生成コードの問題をExcel設計行へ戻すための追跡情報として利用する。`(*1)` 等の付記の厳密な意味は、生成器仕様を別途確認するまで推測しない。

## 10. 検証仕様と合格条件
| 段階 | 検証内容 | 合格条件 |
|---|---|---|
| Excel | シート、マクロ、制御行 | 必須構造が維持される |
| 生成 | CSVPP/生成器の実行 | エラーなしで `.v` が出力される |
| 構文 | Verilogパーサ/コンパイラ | エラーなし（警告は記録） |
| 宣言 | ポート・幅・方向 | 入力仕様と一致する |
| 順序動作 | クロック・リセット・優先順位 | 入力仕様と一致する |
| FSM | 初期状態、遷移、到達可能性 | 意図した遷移を満たす |
| 回帰 | 既知のサンプル | 変更前と機能的に等価 |

ツールが実際に未実行の場合、**「生成成功」「コンパイル成功」と記載しない**。未実施と明記する。

## 11. エラー処理
- Excelの書式・コマンドエラー：マニュアルの「エラーメッセージ」シートの形式（例：`CSV File Read Error`、`SEL`、`FILE`、`SEL_DATA`）に従い原因を追跡する。
- Verilog構文エラー：行番号、信号名、関連する `_CELL` コメントを記録し、元の設計セルを特定する。
- 動作不一致：仕様の期待値、実測値、再現条件、対象セル、修正案を提示する。
- 不明なコマンド：推測したパラメータで実行せず、マニュアル・動作例を再確認する。

## 12. AIへの指示テンプレート
> あなたはCSVPP用Verilog RTL設計データの作成支援AIです。入力されたRTL仕様を構造化し、添付の `CSVPP_Verilog_Generation.xlsx` と `csvveri_rtl.xlsx` の実例に従って `model` シートを編集してください。`cmd` と `csvveri_C` は変更しないでください。未確認のコマンド構文は推測で使用せず、確認事項として報告してください。出力は編集済みExcel、変更セル一覧、未確定事項、生成・検証状況としてください。生成コードに問題がある場合は元のExcel行に戻って修正してください。

## 13. 初版の受入試験
**試験A：既存モデル再現** — 元の `csvveri_rtl.xlsx` から生成したVerilogと、既知の `model(1).v` を比較する。ヘッダやコメント等の差は区別し、モジュール構造と機能の一致を判定する。

**試験B：ポート変更** — 既存のポート定義と同じ書式で幅・名称を変更し、宣言が期待通り出力されるか確認する。

**試験C：簡単なレジスタ追加** — 既存の記述パターンを複製し、リセットと更新条件を追加して、生成・シミュレーションを確認する。

**試験D：FSM変更** — 既存状態の遷移条件を変更し、生成コードの条件優先順位と波形を照合する。

各試験で入力仕様、編集セル、生成ファイル、実行ログ、検証結果を保存する。

## 14. 制限事項・今後の課題
1. この文書は**マニュアルと既存サンプルを参照したAI連携設計仕様**であり、すべてのコマンドの列配置・全パラメータを網羅する正式な構文辞書ではない。
2. `model` シートの各コマンド行の詳細な列仕様は、コマンド別の実例を照合してVer.1.1以降で追加する。
3. `csvveri.exe` とCSVPPの実行環境、出力パス、CSV変換条件は環境依存である。
4. 合成可能RTLとテストベンチ専用記述を混同しない。
5. FSMの表現形式、優先順位、未指定条件の扱いは生成結果とシミュレーションで検証する。
6. 複数クロック、CDC、ラッチ回避、パラメータ化、メモリ、構造記述などは追加試験が必要。

## 15. Ver.1.1に向けた推奨作業
`model` シートの**全使用コマンドについて「行番号／B列コマンド／C列以降の意味／生成Verilog行／制約」**の対応表を作る。これをAIの入力ルールとして固定し、既存モデルの再生成テストを通してから、自然言語→Excelの自動生成範囲を段階的に拡張する。
